# Корсик 2.0 — чат-бот адаптации в MAX

> **🚀 Для хакатона:** Быстрый запуск → [БЫСТРЫЙ_СТАРТ.md](./БЫСТРЫЙ_СТАРТ.md) | Готовность проекта → [ГОТОВО_К_ХАКАТОНУ.md](./ГОТОВО_К_ХАКАТОНУ.md)

**Корсик 2.0** — MVP AI-помощника для адаптации новых сотрудников. Целевой канал — чат-бот в MAX: сотрудник проходит короткий персональный маршрут, получает ответы только по согласованной корпоративной базе знаний и при необходимости сам подготавливает обращение HR. Веб-интерфейс в репозитории — не замена MAX, а наглядный стенд для защиты: он повторяет сценарий мессенджера и показывает потоки данных между четырьмя ролями.

Сервер построен на FastAPI и готов принимать сообщения из MAX через webhook. Он ищет подтверждённые фрагменты в локальной базе знаний, указывает документ-источник в ответе и может подключать GigaChat только при наличии релевантного контекста. Если подтверждённого ответа нет, бот не выдумывает его и предлагает подготовить обращение HR. Передача в HR возможна только после явного подтверждения сотрудника.

## Что решает продукт

Первый рабочий день и первые недели часто сопровождаются повторяющимися организационными вопросами: когда и куда выходить, какие документы действительно нужны, кто поможет с доступами и как понять первые задачи. Сотруднику нужен простой личный канал, HR — только те обращения, которые человек решил передать, руководителю подразделения — этап адаптации новичков без чтения их личных диалогов, а руководителю управления — обезличенная сводка тем и рисков за последние семь дней.

Корсик связывает эти роли с разными границами доступа. Личная переписка не превращается в общий дашборд. HR получает подтверждённые обращения, руководитель видит только статус адаптации своей команды, а руководитель управления — только агрегированные метрики. Обратная связь и напоминания добровольны; напоминания включаются отдельно и отменяются командой `/cancel`.

## Роли и сценарии

| Роль | Что получает | Чего не получает |
| --- | --- | --- |
| Новый сотрудник | Маршрут на первые недели, ответы по утверждённым документам, возможность подготовить обращение HR | Необязательных запросов на передачу личных сообщений без согласия |
| HR-менеджер | Явно подтверждённые обращения и агрегированные сигналы | Полную личную переписку сотрудника |
| Руководитель подразделения | Статус адаптации сотрудников команды и повод назначить личную встречу | Содержание их личного диалога с ботом |
| Руководитель управления | Еженедельный обезличенный дайджест тем, тональности и зон внимания | Персональные сообщения и данные конкретного сотрудника |

## Диалог сотрудника в MAX

Команда `/start` запускает четыре вопроса: должность, опыт на похожей позиции, площадка и дата первого рабочего дня. После этого бот формирует понятный маршрут: уточнить время и место выхода у руководителя или HR, проверить только выданный список документов, в первый день познакомиться с командой, первыми задачами, нужными доступами и оборудованием. Бот не просит отправлять документы, пароли, паспортные данные или сведения о здоровье.

Команда `/hr` запускает безопасный сценарий: сотрудник пишет вопрос, видит будущий текст обращения и выбирает «Отправить HR», «Изменить текст» или «Не сейчас». Вопрос не пересылается автоматически. Команда `/status` показывает маршрут, `/help` — подсказку, `/cancel` останавливает опрос, удаляет будущие напоминания и очищает неподтверждённый черновик обращения.

## Архитектура

```text
MAX → POST /webhooks/max → FastAPI → RAG по утверждённой базе знаний
                                      ├→ GigaChat (только с найденным контекстом)
                                      ├→ SQLite: профиль, согласия, обращения, напоминания
                                      └→ ролевые API: HR / руководитель / дайджест
```

`backend/app/integrations/max.py` изолирует транспорт MAX от сценариев бота. После получения доступа к кабинету разработчика MAX в этот адаптер нужно внести точные URL, структуру события, механизм подписи и формат кнопок из актуальной документации. В репозитории намеренно нет выдуманного endpoint или неподтверждённой схемы интерактивных кнопок.

## Быстрый запуск

Нужен Python 3.10+.

```powershell
cd korsik-bot
Copy-Item .env.example .env
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd backend
uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000`. Здесь доступен мессенджерный стенд с четырьмя ролями и `http://127.0.0.1:8000/docs` с интерактивной документацией API.

Для короткого визуального показа без установленного Python можно открыть `backend/app/static/MAX_демо_предпросмотр.html`. Это **автономный сценарий**: он не обращается к серверу, не отправляет обращения HR и не отправляет напоминания. Интерфейс явно сообщает об этом.

### Проверки

```powershell
cd korsik-bot\backend
pytest -q
```

Дополнительно можно проверить JavaScript без запуска браузера:

```powershell
node --check app\static\app.js
```

## Запуск через Docker

```powershell
cd korsik-bot
Copy-Item .env.example .env
docker compose up --build
```

Сервис будет доступен на `http://127.0.0.1:8000`. Локальная SQLite-база хранится в `backend/data/korsik.db` и исключена из Git.

## Подключение GigaChat

GigaChat вызывается только на сервере и только когда RAG уже нашёл релевантные фрагменты утверждённых документов. В демонстрационном режиме модель не требуется: бот отвечает выдержкой из источника.

```env
DEMO_MODE=false
GIGACHAT_AUTHORIZATION_KEY=секрет_из_кабинета_GigaChat
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_VERIFY_SSL=true
```

Никогда не добавляйте секреты в Git, презентацию, чат или клиентский JavaScript. При необходимости корпоративного CA укажите утверждённый путь в `GIGACHAT_CA_BUNDLE`; проверку TLS не отключайте.

## Подключение MAX

Подробная инструкция: [`ПОДКЛЮЧЕНИЕ_MAX_ЧЕРЕЗ_GITHUB.md`](ПОДКЛЮЧЕНИЕ_MAX_ЧЕРЕЗ_GITHUB.md).

После создания bot account и развёртывания на публичном HTTPS-домене webhook будет выглядеть так:

```text
https://ВАШ-ДОМЕН/webhooks/max
```

В `.env` нужно внести только подтверждённые в кабинете MAX значения:

```env
DEMO_MODE=false
MAX_BOT_TOKEN=секрет_бота_MAX
MAX_SEND_MESSAGE_URL=https://endpoint-из-актуальной-документации-MAX
MAX_AUTH_HEADER=Authorization
MAX_AUTH_VALUE_TEMPLATE=Bearer {token}
MAX_WEBHOOK_SECRET=длинный_секрет_для-проверки-webhook
```

После первого входящего сообщения бот сохраняет реальный `chat_id`; только после этого и только при согласии сотрудника могут доставляться отложенные напоминания. Идентификатор пользователя не подменяется идентификатором чата.

## База знаний

Источники лежат в `backend/data/knowledge_base`. Перед защитой и тем более production-использованием замените их утверждёнными материалами компании. Не загружайте черновики, персональные данные и непроверенные инструкции. Для пакетного импорта согласованных файлов:

```powershell
python backend/scripts/ingest_documents.py "C:\путь\к\утверждённым_документам" backend/data/knowledge_base
```

Затем перезапустите сервис или вызовите `POST /api/admin/reload-knowledge`. Сканированные PDF не импортируются без проверки OCR, чтобы не допустить тихого искажения нормативного текста.

## Демонстрация для экспертов

Полный сценарий — в [`docs/DEMO_SCRIPT.md`](docs/DEMO_SCRIPT.md), краткий текст выступления — в [`docs/EXPERT_PITCH.md`](docs/EXPERT_PITCH.md). Рекомендуемая последовательность: показать `/start`, ответ на вопрос с источником, безопасное обращение HR с подтверждением, затем три ролевых экрана. На защите важно назвать веб-интерфейс демонстрационным стендом, а рабочим каналом — будущего MAX-бота через webhook.

## Ограничения MVP и следующий шаг

Проект не следует выдавать за готовую production-систему. Вне `DEMO_MODE` текущая защита ролевых API использует один служебный токен; до реального запуска необходимы корпоративный SSO, RBAC и проверка принадлежности сотрудника конкретному руководителю. MAX-адаптер должен быть окончательно сопоставлен с актуальной документацией после доступа к кабинету разработчика. Периодическая аналитика предназначена для улучшения адаптации, не для кадровых решений по отдельному человеку.

Подробнее о границах данных, согласиях и обязательных доработках — в [`docs/PRIVACY_AND_LIMITATIONS.md`](docs/PRIVACY_AND_LIMITATIONS.md).
