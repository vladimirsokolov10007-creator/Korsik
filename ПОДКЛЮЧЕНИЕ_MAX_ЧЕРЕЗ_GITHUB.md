# Как превратить этот репозиторий в работающий чат-бот MAX

## Важное различие

GitHub хранит исходный код и запускает автоматические проверки. Он не является сервером чат-бота и не принимает сообщения от MAX. После загрузки репозитория на GitHub его нужно развернуть на сервисе с публичным HTTPS-адресом, например Render, Railway, Yandex Cloud или корпоративном сервере. Именно этот публичный сервер MAX будет вызывать через webhook.

В репозитории уже есть `Dockerfile`, `render.yaml`, `docker-compose.yml`, `.env.example` и GitHub Actions. Поэтому код можно загрузить на GitHub без переработки, а затем импортировать репозиторий в сервис развёртывания.

## Что уже работает как бот

Сервер принимает `POST /webhooks/max`, получает текст пользователя, создаёт или находит профиль сотрудника, определяет команду либо вопрос и отправляет ответ в MAX через отдельный API-адаптер. У сотрудника есть чатовый сценарий без веб-формы:

```text
/start
→ должность
→ «новичок» или «опыт есть»
→ площадка GrPP / GTP / Luzhniki
→ дата первого рабочего дня
→ персональный маршрут и напоминания
```

Команды `/status`, `/help`, `/hr` и `/cancel` работают непосредственно в диалоге с ботом. Обычный вопрос проходит RAG-поиск по утверждённой базе знаний. При отсутствии источника Корсик создаёт обращение HR и не генерирует неподтверждённый ответ.

## Шаг 1. Создать GitHub-репозиторий

Создайте в GitHub новый **private** repository, например `korsik-max-bot`. Распакуйте архив проекта, откройте терминал внутри папки `korsik-bot` и выполните команды:

```powershell
git init
git add .
git commit -m "Initial Korsik MAX bot"
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/korsik-max-bot.git
git push -u origin main
```

Перед `git add .` убедитесь, что файл `.env` не добавлен в индекс. Он уже указан в `.gitignore`. В GitHub должен попасть только `.env.example`, где нет настоящих секретов.

## Шаг 2. Развернуть сервер

Самый быстрый вариант — импортировать GitHub-репозиторий в Render как Blueprint: сервис сам увидит `render.yaml`, соберёт Docker-образ и выдаст публичный URL вида `https://korsik-max-bot.onrender.com`.

В настройках сервиса задайте секретные переменные окружения. Не размещайте их в GitHub, README, презентации или переписке:

```env
DEMO_MODE=false
GIGACHAT_AUTHORIZATION_KEY=секрет_из_кабинета_GigaChat
MAX_BOT_TOKEN=секрет_бота_MAX
MAX_SEND_MESSAGE_URL=точный_URL_отправки_из_документации_MAX
MAX_WEBHOOK_SECRET=длинное_случайное_значение
DASHBOARD_ADMIN_TOKEN=длинное_случайное_значение
APP_BASE_URL=https://ваш-публичный-домен
```

После деплоя откройте `https://ваш-публичный-домен/api/health`. Корректный ответ содержит `status: ok`. Этот адрес не раскрывает секреты.

## Шаг 3. Внести точные параметры из кабинета MAX

Документация API зависит от версии и прав конкретного bot account. Поэтому в проекте нет выдуманного endpoint’а. В кабинете разработчика MAX нужно сверить четыре вещи: адрес отправки сообщений, место передачи идентификатора чата или пользователя, регистрацию webhook и способ проверки подлинности входящего webhook.

В `.env` предусмотрены все необходимые параметры. Если документация MAX указывает, что идентификатор получателя должен быть в JSON-теле, используйте:

```env
MAX_RECIPIENT_LOCATION=body
MAX_RECIPIENT_FIELD=chat_id
```

Если идентификатор нужно передавать как query-параметр, используйте:

```env
MAX_RECIPIENT_LOCATION=query
MAX_RECIPIENT_FIELD=chat_id
```

Если идентификатор должен быть частью URL, используйте:

```env
MAX_RECIPIENT_LOCATION=url_template
MAX_SEND_MESSAGE_URL=https://api.example/messages?chat_id={chat_id}
```

Также укажите в `MAX_WEBHOOK_SECRET_HEADER` точное имя заголовка, если MAX отправляет согласованный секрет или подпись. В production-режиме сервер намеренно не принимает неподписанный webhook. Если MAX использует криптографическую подпись, а не секрет в заголовке, соответствующую проверку нужно добавить в `backend/app/routers/webhook.py` по точной схеме из официальной документации.

## Шаг 4. Зарегистрировать webhook в MAX

В кабинете MAX укажите публичный адрес:

```text
https://ваш-публичный-домен/webhooks/max
```

Затем напишите созданному боту в MAX команду `/start`. Бот не требует HTML внутри MAX: вся логика выполняется сервером, а MAX показывает обычные сообщения чат-бота.

## Шаг 5. Проверить реальный round-trip

Проверка считается успешной, если пользователь отправляет `/start`, проходит четыре коротких вопроса, затем задаёт «Какой рабочий график?» и получает ответ с названием документа-источника. После вопроса, которого нет в базе знаний, должно появиться открытое обращение HR, а не выдуманный ответ.

## Перед защитой

Не используйте скриншоты или демонстрационные данные как утверждённые кадровые сведения. Загрузите в `backend/data/knowledge_base` только актуальные согласованные документы и перезапустите сервис. Интерактивные кнопки MAX выключены по умолчанию параметром `MAX_SEND_INTERACTIVE_BUTTONS=false`: включать их можно только после сверки формата JSON-кнопок в активной версии API MAX. Текстовый чат, команды и серверная обработка webhook от этого не зависят.
